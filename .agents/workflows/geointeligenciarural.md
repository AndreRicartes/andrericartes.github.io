Content para o Workflow: "Engine de Autoridade André Ricartes"
1. Introdução e Governança do Workspace
Este Workspace tem como objetivo gerenciar a presença digital de André Ricartes | Geointeligência Rural. Ele não é um editor de laudos, mas um transformador de conhecimento técnico em ativos de busca (SEO). O foco é garantir que qualquer assunto — da análise multitemporal no Pantanal à infraestrutura rodoviária com IA — siga o padrão de 36 anos de experiência do autor.

2. Categorização de Assuntos (Multitemas)
Para garantir que o Antigravity aplique as regras corretas, cada novo post deve ser classificado em um destes pilares:

Estudo de Caso (Perícia/Posse): Foco em prova técnica, séries históricas e evidências biológicas (Ex: Fazenda Bela Vista).

Inteligência Territorial (Infraestrutura): Foco em alta resolução, monitoramento de ativos e logística (Ex: Ecovias).

Big Data & Dev (Tecnologia): Foco em Python, DuckDB, automação e arquitetura de dados agro.

Inovação e IoT: Foco em sensores, Agricultura 5.0 e prototipagem.

3. Protocolo de Transcrição: Do Técnico para o Digital
Ao trazer informações de um laudo ou projeto para este Workspace, siga estas diretrizes:

Generalização Estratégica: Mantenha os dados que provam a expertise (resolução de 2m, sensores CBERS-4A, análise 2010-2026), mas sanitize dados sensíveis (nomes e CPFs).

Extração de Conceitos Proprietários: Identifique termos que só você usa ou domina, como "Benfeitoria Biológica" ou "Inércia Produtiva". Esses termos devem ser destacados com negrito ou em blocos de citação para criar "ganho de informação" para o Google.

A Prova Visual: O conteúdo deve referenciar imagens que serão salvas em WebP. No texto, descreva o que o sensor captou (ex: "A reflectância no infravermelho próximo revelou a compactação do solo").

4. Diretrizes de SEO e Autoridade (E-E-A-T)
O Antigravity deve validar se o post cumpre os requisitos para não ser confundido com "conteúdo gerado por IA genérica":

Primeiro Parágrafo: Deve ser direto e conter a localização ou a tecnologia principal. Proibido introduções vagas.

Densidade Técnica: O texto deve citar ao menos 3 entidades técnicas (ex: Sentinel-2, GeoPandas, NDVI, RTK, Prova Pericial).

Otimização Local: Para assuntos de geoprocessamento, a cidade ou região (Bebedouro-SP, Paiaguás-MS) deve aparecer nos subtítulos (H2).

5. Estrutura de Código e Configuração (Head & Body)
O workflow deve garantir que o código gerado para o GitHub Pages siga esta anatomia:

Header: Injeção automática de Meta Description (máx 155 caracteres) e JSON-LD TechArticle.

Body: Uso de Tailwind CSS respeitando a paleta industrial (agtech-emerald, agtech-black).

Footer: Call to Action (CTA) contextual. Se o post é técnico, o CTA é "Solicitar Laudo". Se o post é sobre tecnologia, o CTA é "Consultoria em Big Data".

6. Otimização de Ativos (Media Rules)
O Workspace deve impor a regra de performance:

Imagens: Conversão obrigatória para WebP.

Alt-Text: Deve ser uma descrição técnica para o Google Imagens. Ex: alt="Mapa multitemporal de uso do solo 2010-2026 região do Paiaguás via satélite SPOT e Sentinel".

Gráficos: Preferência por vetores (SVG) ou tabelas HTML responsivas para dados de compactação e biomassa.

7. Workflow de Revisão Final (Checklist de Saída)
Antes de realizar o deploy para andrericartes.github.io, o conteúdo deve passar por:

Validação de Tom de Voz: O texto soa como um especialista com 36 anos de campo?

Verificação de Links: Existe ao menos um link interno e um externo para fontes de autoridade (INPE, NASA, Planalto)?

Consistência de Termos: "Benfeitoria Biológica" está grafada corretamente e explicada?

Performance Check: O HTML gerado está limpo e sem scripts desnecessários?
